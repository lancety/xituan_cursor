# 正文图 flex 布局

断点宽度不写入标签，也不使用视口 `@media`。同一行连续图片是一个 flex 行，整行只共用一组 `min`、`max` 和 `align`。行内每张图用这同一组约束平分宽度。任何情况下都不超过容器宽度的 100%。容器比 `min` 更窄时，最小宽度按容器的 100% 计算。

## 标签

图片 title 只保留三个属性，单位是 px，对齐取值 `left` / `center` / `right`：

```text
![图片](path "min=160 max=320 align=center")
```

- 一行一组：`min`、`max`、`align` 属于整行，不按单张图各写各的。三个值写进这一行每一张图的 title，并且保持相同。阅读时以该行第一张图为准，后面几张若被手改得不一致，忽略它们的差异。
- `max`：这一行里每张图的宽度上限。
- `min`：这一行里每张图的宽度下限，也是还能再挤进一张图的宽度。`min` 不能大于 `max`。
- `align`：一行没占满时，剩余空白靠左、居中或靠右。单张图就是只有一张的行。
- 不写 `min`：下限为 0。不写 `max`：上限为容器的 100%。不写 `align`：`center`。
- 设置界面的初始值是 `min=160`、`max=320`、`align=center`。商户在界面里改，范围 64–1200，按 8 对齐，并且 `min` 不能大于 `max`。
- 不另设期望宽度。`max` 就是这一行里每张图想要的宽度；空间够就停在 `max`，不够就在 `min` 和 `max` 之间压缩，再不够就换行。多一个期望值时，有剩余空间仍会涨到 `max`，期望宽度几乎看不出来。
- 没有换行的连续图是一组。设置界面确认后，这一组每一张都写成同一个 `min`、`max`、`align`。
- 已有 `dw=480` 读成 `min=480 max=480`。预览里改过之后写成 `min` / `max` / `align`。

加载哪张 `_w64` / `_w128` / `_w256` / `_w512` / 原图仍用 `max` 选档（大于 512 用原图）。容器变窄时不另选文件，失败仍回退原图。

## 排列规则

源码里同一段落、中间只有空白、没有换行的连续图片是一行。有换行（`remark-breaks` 的 `<br>`，或小程序里的 linebreak）就拆成下一行。

```text
![a](p1 "min=160 max=320 align=center") ![b](p2 "min=160 max=320 align=center")
```

上面两张在一个 flex 行里。各自单独成行则上下排列。

Web 与小程序用同一套 CSS，不读窗口宽度：

```css
.xt-md-img-row {
  display: flex;
  flex-wrap: wrap;
  align-items: flex-start;
  gap: 8px;
  width: 100%;
  justify-content: flex-start; /* center / flex-end */
}
.xt-md-img-item {
  flex: 0 0 var(--xt-col);
  width: var(--xt-col);
  max-width: 100%;
}
.xt-md-img-item img {
  display: block;
  width: 100%;
  height: auto;
}
```

同一组每一张用同一个宽度，最后一行张数少也不再单独放大。列数取「按 `min` 一行能放几张」和「实际张数」里较小的那个。宽度是这一列分到的大小，但不超过 `max`，也不超过容器。间距 8px。容器比 `min` 更窄时，每张按容器的 100%，一列一张。`align` 只决定没占满的空白靠左、居中或靠右。

纯 `flex-grow` 会把最后一行拉宽，所以阅读端按正文容器的实际宽度算出列宽，再写到每张图上。Web 用容器宽度，商家端和客户端用行的 `onLayout`，小程序用该行的布局宽度。都不读窗口 media。

以默认 `min=160`、`max=320`、间距 8、5 张为例：容器 360 是 2+2+1，全部约 176；640 是 3+2，全部约 208；720 是 4+1，全部约 174；1200 是一行 5 张，约 234。最后一行和上面使用同一宽度。

```mermaid
flowchart LR
  sameLine[同一行连续图片] --> flexRow[flex行 wrap]
  flexRow --> cols[列数取min能放的列和张数的较小值]
  cols --> sameSize[每张同一宽度且不超过max]
  sameSize --> lastRow[最后一行沿用这个宽度]
```

## 添加

工具栏的图片按钮先让商户选「添加图片」或「添加图组」。两种都进入同一个设置界面：最小宽度、最大宽度、左对齐 / 居中 / 右对齐。初始值 160、320、居中。

- 添加图片：选一张。CMS 仍先走现有裁剪工作室，工作室里的显示宽度去掉。确认导出后进入设置界面，再插入这一张。
- 添加图组：一次选多张。不逐张打开裁剪工作室，每张按长边不超过 2048 的 webp 导出。设置界面只有这一组的最小、最大和对齐。确认后把这些图插在同一行，图和之间只有空格，没有换行。
- 当前若在预览：先提示并切到编辑模式，再打开上面的选择。这一次不选图。
- 插入位置是编辑区光标，前后不加换行。现在 CMS 的 `insertText(\`\\n${image}\\n\`)` 和商家端的 `insertAtSelection(..., \`\\n${markdown}\\n\`)` 都去掉。要上下排，商户自己回车，或把光标放到新的空行再添加。
- 新图落到某一行后，这一行里中间没有换行的图全部写成这次界面上的 `min`、`max`、`align`。

商家端没有裁剪工作室。添加图片是选一张，添加图组是选多张，然后都是同一个最小、最大、对齐界面。

## 预览里再调整

预览里不再用边缘拖拽条改宽度。现有右缘、下缘、右下角拖拽条去掉。

点击预览中的图片，再次打开同一个设置界面。单独一张时改这一张。它和相邻图在同一行、中间没有换行时，界面按图组打开，确认后这一行每一张都写成新的最小、最大和对齐。这个点击不重新裁剪、不重新上传。

帮助文案改成：点击预览中的图片，可改最小宽度、最大宽度和对齐；同一行的图一起变。

CMS 设置界面放在新闻编辑器旁，预览点击从 [MarkdownEditorImage.tsx](xituan_cms/src/components/news/MarkdownEditorImage.tsx) 打开。商家端预览点击打开同样三项的界面。编辑模式里的 `min=` / `max=` 仍是同一份数据。

## 代码落点

共享解析放在各应用已有的 [markdown-body-image.util.ts](xituan_cms/submodules/xituan_codebase/utils/markdown-body-image.util.ts)（backend、cms、site、wechat、merchant、customer、platform 各一份保持同一套函数）：解析 `min` / `max` / `align`，把旧 `dw` 映射为两者相等，格式化 title，把同一行每一张图写成同一组布局属性。阅读端用该行第一张图的一组值套到整行。

阅读端按同一分组规则包 flex 行：

- CMS 预览与 [SiteMarkdownBody.tsx](xituan_site/src/components/content/SiteMarkdownBody.tsx)：自定义段落渲染，把只隔空白的连续 `img` 收成一行。
- 小程序 [parser.js](xituan_wechat_app/packageUtil/components/wemark/parser.js) 把连续 `image`（中间不是 linebreak）收成 `image_row`，[wemark.wxml](xituan_wechat_app/packageUtil/components/wemark/wemark.wxml) 用 flex 容器画出；[richtext.js](xituan_wechat_app/packageUtil/components/wemark/richtext.js) 同步这套宽度。
- [商家端 MarkdownBody.tsx](xituan_app_merchant/src/components/MarkdownBody.tsx) 与客户端同结构组件：连续图片合成一个 `flexWrap: 'wrap'` 的行，宽度用容器 `onLayout`。
